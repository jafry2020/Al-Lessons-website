  - question: "Why do transformers need positional encodings?"
    shortAnswer: |
      Attention is permutation-invariant: shuffling the input tokens gives the same output (just shuffled). Position must be encoded explicitly. Common choices: absolute sinusoidal, learned, and RoPE.
    detailed: |
      A transformer's attention treats inputs as a bag of vectors — position is not in the formula. Without explicit encoding, "the cat sat" and "sat cat the" would produce the same outputs (permuted accordingly).

      Standard approaches:

      **Absolute sinusoidal** (original transformer): add a sin/cos vector with frequencies geometrically spaced. Each position gets a unique vector. Generalises somewhat to longer sequences than training.

      **Learned absolute**: each position has a learnable embedding. Used in BERT, GPT-2. Doesn't extrapolate beyond training length.

      **Rotary Position Embedding (RoPE)** (Su et al., 2021): rotate Q and K vectors by an angle proportional to position. Encodes relative positions naturally; extrapolates well. Used in Llama, Mistral, PaLM, most modern LLMs.

      **ALiBi** (Press et al., 2021): add a bias to attention scores that linearly decreases with distance. Simple, no learned parameters, decent extrapolation. Used in BLOOM, some Mosaic models.

      In 2026 for new LLMs: RoPE is the dominant choice. ALiBi is a credible alternative for long-context extrapolation.
    pitfalls:
      - "RoPE's frequency 'base' (default 10000) determines how long the model can extrapolate. Increasing base extends context (used in long-context Llama variants)."
  - question: "What's the difference between encoder-only, decoder-only, and encoder-decoder?"
    shortAnswer: |
      Encoder-only (BERT): bidirectional self-attention, no causal mask, trained with masked language modelling. Decoder-only (GPT): causal self-attention, trained autoregressively. Encoder-decoder (T5): both, plus cross-attention between them.
    detailed: |
      **Encoder-only** (BERT, RoBERTa). Bidirectional attention — every token sees every other. Trained with masked language modelling (predict 15% randomly masked tokens). Strong at understanding tasks (classification, sequence labelling, sentiment); weak at generation.

      **Decoder-only** (GPT family, Llama, Mistral, most modern LLMs). Causal self-attention only. Trained on next-token prediction. Strong at both understanding (via prompting) and generation. The dominant architecture for LLMs in 2026.

      **Encoder-decoder** (T5, BART, original Transformer). Encoder is bidirectional; decoder is causal; cross-attention connects them. Used in translation, summarisation, sequence-to-sequence tasks. Still common in some research and specialised production systems.

      In 2026, decoder-only LLMs have largely subsumed the other categories. GPT-style models can do classification (via prompting), translation (via prompting), generation, and reasoning. The single architecture covers everything via task description in natural language.
    pitfalls:
      - "BERT-style encoders are still strong for cheap classification at fixed input length. Don't migrate to decoder-only just for fashion."

  A transformer block has two sub-layers: multi-head self-attention and a position-wise FFN, each
  wrapped in residual + norm. Stack N of them, add positional encoding to the embedding layer, and
  you have the architecture that powers BERT, GPT, Llama, ViT, Stable Diffusion (most of),
  AlphaFold, and most of modern AI. The original 2017 design has been refined (pre-norm, RoPE,
  RMSNorm, GQA, FlashAttention) but the template hasn't been replaced.
</TldrCallout>

## The transformer block

The fundamental unit:

```
x → LayerNorm → Multi-head attention → + x
       ↓ (this is now y)
y → LayerNorm → FFN → + y
       ↓
output
```

Two sub-layers. Each:

1. Norm the input.
2. Apply the sub-layer (attention or FFN).
3. Add the original input (residual).

The residual + norm wrapping is what makes deep stacks work (A5.3 + A4.6).

Stack N of these blocks. Add input embeddings + positional encoding at the bottom, an output projection at the top, and you have a complete transformer.

## What's inside each sub-layer

**Multi-head attention (A5.4):**

- Project input X to Q, K, V via learned matrices.
- Split into h heads, each with dim d/h.
- Compute attention for each head independently.
- Concatenate and project.

**Position-wise FFN:**

- Linear(d → 4d).
- Activation (GELU in classical, SwiGLU in modern).
- Linear(4d → d).

The FFN is "position-wise" because the same MLP is applied independently to each position's representation. No interaction across positions — that's the attention's job.

Most parameters live in the FFN (2 × 4d²). Most compute on long sequences lives in the attention (O(n² · d)).

## Positional encoding

Attention is permutation-invariant: shuffle the tokens and the output shuffles the same way. Without explicit positional information, the model has no notion of order.

Three main approaches:

| Method              | Where it lives                | Used in                                |
| ------------------- | ----------------------------- | -------------------------------------- |
| Absolute sinusoidal | Added to input embeddings     | Original transformer                   |
| Learned absolute    | Added to input embeddings     | BERT, GPT-2                            |
| Rotary (RoPE)       | Rotates Q and K               | Llama, Mistral, PaLM, most modern LLMs |
| ALiBi               | Adds bias to attention scores | BLOOM, some Mosaic                     |

**RoPE** rotates each Q and K vector by an angle proportional to position. The attention score between positions i and j ends up depending on (i − j) — relative position — naturally. Extrapolates somewhat to longer sequences than training; modern long-context LLMs increase RoPE's frequency base to extend further.

**ALiBi** adds a position-dependent bias: scores[i, j] -= m · |i − j| with a per-head slope m. No learned parameters; extrapolates well.

In 2026 for new LLM training: RoPE is the dominant choice. The original sinusoidal encoding is mostly historical.

## Three families: encoder-only, decoder-only, encoder-decoder

| Family          | Attention          | Trained with          | Examples            | Best for                                        |
| --------------- | ------------------ | --------------------- | ------------------- | ----------------------------------------------- |
| Encoder-only    | Bidirectional      | Masked LM             | BERT, RoBERTa       | Classification, retrieval, NER                  |
| Decoder-only    | Causal             | Next-token prediction | GPT, Llama, Mistral | Generation, reasoning, everything via prompting |
| Encoder-decoder | Both (sep modules) | Sequence-to-sequence  | T5, BART            | Translation, summarisation                      |

In 2026, decoder-only LLMs have absorbed most use cases. A GPT-style model can do classification (prompt + read first-token logits), translation (prompt with source + "Translate:"), generation, summarisation, reasoning. The single architecture covers everything via task-as-prompt.

BERT remains the choice for high-throughput classification at fixed input lengths (often cheaper). T5 still appears in specialised settings (some Google products, research).

## A full transformer, top to bottom

```
Input tokens → Embedding lookup → Add positional encoding
       ↓
Block 1: Pre-LN → Attention → Residual → Pre-LN → FFN → Residual
       ↓
Block 2: same
       ↓
...
       ↓
Block N: same
       ↓
Final LayerNorm
       ↓
Output projection (to vocabulary)
       ↓
Softmax → token probabilities
```

For Llama-2-7B: N=32 blocks, d=4096 (model dim), FFN dim ~11000 (SwiGLU is leaner than 4x), 32 attention heads, 8 KV groups (GQA), vocab ~32k, RoPE positional, RMSNorm, SwiGLU.

The whole forward pass on one token is a stack of matrix multiplies and a softmax at the end. Conceptually simple; the engineering to make it fast at 7B–405B parameters is the hard part.

## Why the same architecture for everything

Vision Transformer (ViT) splits an image into 16×16 patches, projects each to a token, and runs a standard transformer encoder. Same blocks; different embedding.

Audio Transformers (Whisper) convert spectrograms to tokens via 1D conv stem; same blocks.

DiT (Diffusion Transformer) replaces U-Net in diffusion with transformer blocks; same blocks.

The transformer "block" turned out to be a generic sequence-processing primitive that works on anything you can tokenise. This generality is one of the reasons foundation models (Module 6+) generalise across modalities.

## Parameter and compute scaling

For a transformer with N layers, hidden dim d, FFN factor 4, sequence length n:

- **Parameters per block** ≈ 12d² (4d² for attention proj, 8d² for FFN).
- **Total parameters** ≈ 12 · N · d² (plus embeddings, output head).
- **Compute per token (forward)** ≈ 24 · N · d² (FFN dominates) + 2 · N · n · d (attention).
- **Compute for training** ≈ 6 × forward (forward + backward + optimizer).

For typical models:

| Model         | N   | d     | Params | Train FLOPs (estimated) |
| ------------- | --- | ----- | ------ | ----------------------- |
| GPT-2 (small) | 12  | 768   | 124M   | ~10²⁰                   |
| BERT-large    | 24  | 1024  | 340M   | ~10²¹                   |
| GPT-3         | 96  | 12288 | 175B   | ~10²³                   |
| Llama-2-7B    | 32  | 4096  | 7B     | ~10²²                   |
| Llama-2-70B   | 80  | 8192  | 70B    | ~10²⁴                   |

The scaling laws (A5.7) tell you the compute-optimal ratio of parameters to training data.

## The architecture is mature

In 2026 the transformer architecture has converged. Modern LLM training scripts are remarkably similar across organisations. The interesting variation is in:

- **Data** — what tokens you train on, how many, in what mix (Module 6, 8).
- **Scaling** — choosing parameter count and training tokens (A5.7).
- **Inference efficiency** — quantisation, KV-cache, batching (Module 8).
- **Modern refinements** — RMSNorm vs LayerNorm, SwiGLU vs GELU, GQA vs MHA, RoPE base, sliding window length (A5.6).
