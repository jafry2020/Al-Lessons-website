  When k-means fails — irregular shapes, unknown k, varying density — the right tools are
  density-based clustering (DBSCAN, HDBSCAN) for arbitrary shapes and hierarchical clustering for
  inspecting the cluster structure as a tree. In production, UMAP + HDBSCAN on embeddings is the
  modern default for clustering text or image data.
</TldrCallout>

## DBSCAN: density-based clustering

DBSCAN (Ester et al., 1996) defines a cluster as a connected region of dense points. Two parameters:

- **eps (ε)** — the neighbourhood radius.
- **min_samples** — the minimum number of points in an eps-radius ball for a point to be considered a "core point."

Every point falls into one of three categories:

- **Core point.** Has ≥ min_samples neighbours within eps. Anchors a cluster.
- **Border point.** Within eps of a core point but doesn't itself meet the density threshold. Joins the cluster.
- **Noise point.** Reachable from no core point. Gets label −1.

The output: a number of clusters of arbitrary shape, plus a noise set. No need to pre-specify k.

<AnalogyCallout>
  Imagine spreading marbles on a table. A cluster is any group of marbles where every marble has at
  least four neighbours within an inch. Marbles too far from the crowd are loners — noise. The
  clusters can be any shape: a circle, a crescent, a long snake. DBSCAN finds them all.
</AnalogyCallout>

## Picking eps with the k-distance plot

For each point, compute its distance to its k-th nearest neighbour (where k = min_samples − 1). Sort and plot. The curve is mostly flat then bends upward — the bend is your eps. This is the closest thing to an "objective" choice DBSCAN allows.

Default rule of thumb for min_samples: 2 × dimensionality. For 2D data, min_samples = 4 is a sensible start; for 10D, 20.

The catch: a single eps can't fit clusters with very different densities. A tight cluster and a sparse one need different eps. This is exactly what HDBSCAN solves.

## HDBSCAN: the modern default

HDBSCAN (Campello et al., 2013) runs DBSCAN at all eps levels simultaneously and extracts the most _stable_ clusters — those that persist across a wide range of eps. The result:

- One main hyperparameter: `min_cluster_size`.
- Handles varying density.
- Returns probabilistic cluster membership.

For clustering text embeddings (BERTopic, top2vec workflows), image embeddings (medical imaging cohorts), or anything where you don't want to babysit eps, **HDBSCAN is the default to reach for**. The Python library `hdbscan` is standard; sklearn 1.3+ ships it as `HDBSCAN`.

## Hierarchical clustering and dendrograms

Hierarchical agglomerative clustering starts with every point as its own cluster, then repeatedly merges the two closest clusters. The merge order forms a **dendrogram**:

- Bottom: each leaf is a point.
- Going up: clusters merge at heights proportional to their distance.
- Top: everything is one cluster.

To get k clusters, cut the dendrogram at a height that crosses exactly k branches.

| Linkage  | Cluster distance =                  | When to use                                      |
| -------- | ----------------------------------- | ------------------------------------------------ |
| single   | min point-to-point distance         | Chained/elongated clusters; sensitive to bridges |
| complete | max point-to-point distance         | Compact, spherical clusters                      |
| average  | mean pairwise distance              | Balanced; good general default                   |
| Ward     | increase in within-cluster variance | Most popular; produces k-means-like clusters     |

Strength: the dendrogram is _diagnostic_. A clear gap before the final few merges means the data really does have natural clusters; a smooth dendrogram means it doesn't.

Weakness: O(n²) memory, O(n²·log n) time at best. Impractical above ~10⁴–10⁵ points without approximations.

## Picking the algorithm — a cheat sheet

| Situation                                        | Reach for                                    |
| ------------------------------------------------ | -------------------------------------------- |
| Need a fast first cut on tabular data            | k-means or mini-batch k-means                |
| Clusters look like blobs and you have a target k | k-means                                      |
| Clusters are weird shapes or you don't know k    | DBSCAN (single density) or HDBSCAN (varying) |
| Want a tree of cluster structure                 | Hierarchical (Ward)                          |
| Clustering high-dim embeddings                   | UMAP → HDBSCAN                               |
| Vector database / billion-scale                  | Faiss IVF (k-means under the hood)           |

The single biggest meta-rule: visualise your data first (2D projection with UMAP, t-SNE, or PCA — covered in A3.4 and A3.5). If the projection shows obvious blobs, k-means works. If it shows shapes or chains, switch.

## In practice

For most modern clustering work — especially anything involving embeddings — the pipeline is:

1. Embed (with a learned model: sentence-transformers, CLIP, a domain-specific encoder).
2. Reduce dimensions (UMAP to 5–10 dims).
3. Cluster (HDBSCAN with a sensible min_cluster_size).
4. Inspect each cluster (manually, or by passing samples to an LLM for labelling).

The classical algorithms — k-means, DBSCAN, hierarchical — are building blocks. The intelligence in the modern pipeline lives in the embeddings, not the clustering algorithm.
